# 在线内容源：作者不提供，需要你自己接

本仓库是**个人作品的 as-is 分享版**，设计上只处理**你自己的本地曲库**：扫描、播放控制、
歌词解析、每日推荐排序。

**从第三方音乐站点检索 / 试听 / 下载 / 抓取歌词这一整类能力，本仓库不包含实现，作者也不提供。**
原因很简单：这类功能要落地，绕不开版权与第三方服务条款，作者不想把这份风险随代码一起发出去。

代码里为它们留了**接口占位**——函数名与签名在，函数体恒返回空值。
所以整份服务能正常启动、本地功能一个不少，只是这些接口永远给你「没有结果」。

要补上这部分，**请自己接，并自己承担合规责任**。这份文档只说清「接入点在哪、怎么接」。

每个占位函数的函数体里都有一行标记，搜它能定位全部 27 处：

## 一之补：仓库里保留的两处联网能力（默认关闭）

有两处**没有**做成占位，因为它们是各家官方公开 API、且必须由你自带凭据才会启用，
默认状态下完全不会发出请求：

| 源 | 用途 | 开启条件 |
|---|---|---|
| Last.fm（`src_lastfm`） | 相似艺人 / 标签 → 推荐 | 在配置里填自己的 `api_key` 并 `enabled` |
| ListenBrainz（`src_listenbrainz`） | 按用户的收听历史出推荐 | 填自己的 `user` 并 `enabled` |

配置文件名 `jy_rec_sources.json`，已在 `.gitignore` 里，**不要提交**。
不配 = 服务不会碰这两个接口，推荐只用本地曲库 + 隐式反馈。

> 如果你连这两个也不想要，把 `src_lastfm` / `src_listenbrainz` 置空即可，不影响其它功能。

## 二、你可以怎么办

### 做法 0：什么都不接（默认，也是作者的用法）

本地曲库浏览、播放控制、队列、歌词解析与逐行微调、每日推荐——全部可用，只是候选池只有本地。

| 功能 | 状态 |
|---|---|
| 本地曲库浏览 / 播放控制 / 队列 | ✅ |
| 歌词解析、双语配对、逐行时间微调 | ✅（不联网补词） |
| 每日推荐（本地 + 隐式反馈 + MMR 重排） | ✅（候选池 = 本地曲库） |
| 主题歌单 / 标签推荐 | ⚠️ 能用，但词条命中率低于有在线源时 |
| 在线搜索、在线试听、下载到本地 | ❌ 空结果 |
| 联网封面 / 联网歌词补全 | ❌ 空结果（回落到本地） |

### 做法 1：只接歌词补全（风险面最小）

只填这 6 个：`nc_get` `_nc_query` `_nc_pick` `nc_lyric` `_nc_lyric_raw` `nc_match`。
不碰检索与下载链路，改动集中、出错也好回退。

### 做法 2：接在线检索 + 试听

需要**整条链路**一起接，缺一环就用不了：

```
jy_*_search  →  jy_*_url  →  resolve_download_url  →  jy_download / download_song
   （搜）        （取直链）        （统一直链解析）        （落盘给播放器）
```

另外 `src_netease` / `src_qqmusic` / `_netease_weapi` 是源适配层，需要按你的数据源形态改写；
`fetch_song` / `_wy_pic_url` / `_plcov_music` 决定歌曲详情与封面从哪来。

## 三、接完自己复核

- `python3 -m py_compile server/server.py`
- 起服务后打 `/api/health` 与 `/api/search?q=test`，确认不再返回空
- 前端「设置 → 音源」页不再显示 `none`
- 播放一次完整流程：搜索 → 点播 → 进度走动 → 播完切下一首（**别只看能不能出声**）
